Темы управления состоянием (сессии, куки, веб-хранилище) — это фундамент веб-разработки. Без них невозможно представить ни авторизацию, ни корзины товаров, ни сохранение пользовательских настроек.

Вот подборка задач, разбитая по языкам. Я составил их так, чтобы вы прошли путь от базового синтаксиса до реальных сценариев использования и вопросов безопасности.

🐘 PHP: Сессии и Куки (Серверная сторона)
В PHP основная работа идет с сервером. Помните, что куки передаются в заголовках, а сессии хранятся на сервере.

Задача 1: Счетчик посещений (Сессии)

Цель: Понять базовый механизм сессий.

Задание: Создайте страницу, которая при каждом обновлении увеличивает счетчик посещений на 1 и выводит его. Если пользователь заходит впервые, выведите "Добро пожаловать!". Используйте session_start() и суперглобальный массив $_SESSION.

Подсказка: Не забудьте проверять наличие ключа в массиве через isset().

Задача 2: "Запомнить меня" (Куки)

Цель: Научиться устанавливать время жизни куки.

Задание: Создайте форму с полем "Имя". При отправке сохраните имя в куку на 30 дней. При повторном заходе на страницу, если кука существует, выводите "Привет, [Имя]!" вместо формы.

Подсказка: Используйте функцию setcookie() с параметром expire (время в секундах: time() + 60*60*24*30).

Задача 3: Простая авторизация (Сессии)

Цель: Понять, как защищаются страницы.

Задание: Сделайте две страницы: login.php (форма ввода логина и пароля) и dashboard.php (секретная страница). Если введен правильный пароль (например, "12345"), запишите в сессию флаг $_SESSION['auth'] = true и перенаправьте на dashboard.php. Если флага нет, dashboard.php должен перенаправлять обратно на форму входа.

Задача 4: Безопасность сессий (Session Fixation)

Цель: Изучить уязвимость кражи сессии.

Задание: Дополните Задачу 3. Сразу после успешного входа пользователя (до записи данных в сессию) используйте функцию session_regenerate_id(true).

Зачем это нужно: Это защищает от атаки, когда злоумышленник заранее подсовывает жертве известный ему ID сессии.

Задача 5: Безопасные куки (HttpOnly и Secure)

Цель: Защита от XSS (межсайтового скриптинга).

Задание: Вернитесь к Задаче 2 и измените установку куки так, чтобы она была доступна только через HTTP-протокол (флаг HttpOnly). Если вы тестируете локально без HTTPS, попробуйте добавить флаг Secure, но помните, что тогда кука не будет работать по HTTP.

Подсказка: Третий параметр в setcookie() — это путь, четвертый — домен, пятый — secure, шестой — httponly.

Задача 6: Выход из системы (Уничтожение сессии)

Цель: Правильное завершение сессии.

Задание: Создайте файл logout.php. При переходе на него сессия должна полностью уничтожаться, а пользователь перенаправляться на главную страницу.

Подсказка: Используйте session_unset(), session_destroy() и удаление куки сессии setcookie(session_name(), '', time()-3600, '/').

🟨 JavaScript: LocalStorage, SessionStorage и Куки (Клиентская сторона)
Здесь вся работа происходит в браузере. Данные хранятся в виде строк.

Задача 1: Переключатель темы (LocalStorage)

Цель: Понять базовый синтаксис localStorage.

Задание: Создайте кнопку, которая переключает тему сайта (например, меняет background-color тега body с белого на черный и наоборот). Выбор пользователя должен сохраняться в localStorage и применяться при перезагрузке страницы.

Подсказка: localStorage.setItem('theme', 'dark') и localStorage.getItem('theme').

Задача 2: Корзина товаров (LocalStorage + JSON)

Цель: Научиться хранить массивы и объекты.

Задание: Создайте кнопку "Добавить товар". При клике добавляйте объект товара (например, {id: 1, name: "Книга"}) в массив. Массив сохраняйте в LocalStorage.

Подсказка: Хранилище работает только со строками. Используйте JSON.stringify() при сохранении и JSON.parse() при извлечении.

Задача 3: Многошаговая форма (SessionStorage)

Цель: Понять разницу между Local и Session storage.

Задание: Сделайте форму из двух шагов. На первом шаге вводится имя, на втором — email. Сохраняйте данные первого шага в SessionStorage, чтобы при случайном обновлении страницы (F5) данные не терялись. Если пользователь закроет вкладку, данные должны исчезнуть.

Задача 4: Синхронизация вкладок (Событие storage)

Цель: Изучить продвинутые возможности LocalStorage.

Задание: Откройте ваш сайт с Задачей 1 (тема) в двух вкладках браузера. Сделайте так, чтобы при переключении темы в одной вкладке, она автоматически менялась и во второй.

Подсказка: Используйте window.addEventListener('storage', (event) => { ... }). Событие срабатывает только в тех вкладках, где изменения не производились.

Задача 5: "Чистый" JS для работы с куками

Цель: Понять, как браузер хранит куки без библиотек.

Задание: Напишите две функции: setCookie(name, value, days) и getCookie(name). Функция установки должна рассчитывать дату истечения. Функция получения должна парсить строку document.cookie.

Важно: Куки в JS выглядят как одна длинная строка name1=value1; name2=value2;. Вам нужно будет использовать методы строк типа .split('; ') и .indexOf('=').

Задача 6: Полная очистка данных (Сброс настроек)

Цель: Закрепить умение удалять данные.

Задание: Создайте кнопку "Сбросить всё". При клике она должна:

Удалить все ключи из localStorage (localStorage.clear()).
Удалить все ключи из sessionStorage.
Удалить все куки, установленные для текущего домена (через JS).
Задача 7: Защита от XSS через LocalStorage (Теория + Практика)

Цель: Понять риски хранения чувствительных данных на клиенте.

Задание: Напишите скрипт, который берет значение из localStorage и вставляет его на страницу через innerHTML. Введите в хранилище строку <script>alert('XSS!')</script> и посмотрите на результат. Затем перепишите скрипт, используя textContent или innerText, чтобы тег вывелся как обычный текст, а не выполнился.

Вывод: Никогда не храните токены авторизации или пароли в LocalStorage, если на странице есть уязвимости XSS.

🚀 Бонусная задача (Связка PHP + JS)
Задача: "Темная тема" на сервере и клиенте

Цель: Понять, как фронтенд и бэкенд делят состояние.

Задание: Сделайте так, чтобы тему сайта можно было менять как через JS (сохраняя в LocalStorage для мгновенного отклика), так и через PHP (сохраняя в куку, чтобы сервер при рендеринге страницы сразу отдавал нужный CSS-класс). При загрузке страницы приоритет должен отдаваться куке (серверу).

Как проверять: Для JS используйте консоль разработчика (F12 -> Console и вкладка Application -> Storage). Для PHP — инструменты разработчика во вкладке Network (смотрите заголовки Set-Cookie) и var_dump($_SESSION).
