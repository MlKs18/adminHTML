🐘 10 задач по Laravel
1. Middleware: Фильтрация по статусу аккаунта

Задача: Создать Middleware EnsureUserIsActive, который проверяет поле is_active у авторизованного пользователя. Если false — прерывает запрос с ошибкой 403.

Цель: Понять жизненный цикл HTTP-запроса и как глобально или точечно (на группу роутов) ограничивать доступ.

2. Middleware + Session: Лог последних посещенных страниц

Задача: Написать Middleware, который при каждом GET-запросе сохраняет URL страницы в сессию (хранить только последние 5 страниц). Вывести этот список в подвале сайта через Blade.

Цель: Научиться работать с сессиями внутри Middleware и передавать данные в глобальные шаблоны.

3. Service Providers: Привязка интерфейса к реализации

Задача: Создать интерфейс PaymentGatewayInterface и его реализацию StripeGateway. Зарегистрировать их привязку ($this->app->bind(...)) в AppServiceProvider. Внедрить интерфейс в контроллер через Dependency Injection.

Цель: Освоить инверсию управления (IoC) и понять, зачем нужны Провайдеры (для регистрации сервисов в контейнере).

4. Service Providers + Cache: Кеширование настроек в Провайдере

Задача: Создать Провайдер, который загружает настройки сайта (из БД или конфига) и кеширует их на 1 час (Cache::remember). Затем этот провайдер должен сделать настройки доступными глобально (например, через View::share).

Цель: Понять, как делать "тяжелые" операции один раз при загрузке приложения, а не при каждом запросе.

5. Policies: Разграничение прав на редактирование

Задача: Создать модель Post и политику PostPolicy. Разрешить автору редактировать только свои посты, а администратору (роль admin) — любые. Использовать метод authorize() в контроллере и директиву @can в Blade.

Цель: Изучить авторизацию (в отличие от аутентификации) на уровне конкретных ресурсов (моделей).

6. Cache: Инвалидация кеша при обновлении

Задача: Кешировать список из 10 самых популярных товаров (Cache::remember('top_products', ...)). Написать логику (например, в модели через Observer), которая сбрасывает этот кеш (Cache::forget) при добавлении нового заказа или изменении товара.

Цель: Понять паттерн "Cache-Aside" и важность сброса устаревших данных.

7. Session: Корзина покупок

Задача: Реализовать корзину покупок, используя только сессии (без БД). Методы: добавить товар (с количеством), удалить товар, очистить корзину, вывести общую сумму.

Цель: Научиться манипулировать массивами данных в сессии (методы session()->push(), session()->get(), session()->forget()).

8. Queue: Тяжелая отправка Email

Задача: При регистрации пользователя отправлять приветственное письмо, но не синхронно. Создать Job (Задание), который симулирует тяжелую операцию (например, sleep(5)), и отправить его в очередь. Настроить драйвер database для очередей.

Цель: Понять, как переносить длительные операции в фоновый режим, чтобы пользователь не ждал ответа сервера.

9. Queue: Цепочка заданий (Job Chaining)

Задача: Создать цепочку из трех заданий: 1) Сгенерировать отчет (PDF), 2) Сохранить его в облако, 3) Отправить ссылку пользователю на email. Использовать Bus::chain(), чтобы они выполнялись строго по очереди.

Цель: Освоить работу со сложными бизнес-процессами в очередях и обработку ошибок в цепочках.

10. Всё вместе: API с защитой и кешем

Задача: Сделать API-эндпоинт для удаления статьи. Он должен:

пройти через Middleware проверки токена;
использовать Policy для проверки, что юзер — автор;
удалить запись и сбросить кеш списка статей;
отправить асинхронное уведомление админу в очередь.
Цель: Закрепить все концепции в одном сценарии.

💚 10 задач по Vue.js (с использованием Composition API)
(Примечание: для выполнения задач 3, 4, 8 потребуется библиотека Pinia и Vue Router).

1. Middleware (Route Guards): Защита роутов

Задача: Настроить Vue Router. Создать глобальный beforeEach навигационный хук (middleware). Если пользователь пытается зайти на /dashboard, а токена в localStorage нет — редиректить его на страницу /login.

Цель: Понять, как работает клиентская маршрутизация и как предотвращать переходы до загрузки компонента.

2. Middleware (Axios Interceptors): Автоматическая подстановка токена

Задача: Создать экземпляр Axios. Настроить перехватчик запросов (request interceptor), который автоматически добавляет Authorization: Bearer <token> в заголовки. Настроить перехватчик ответов (response interceptor): если сервер возвращает 401 (Unauthorized) — очищать токен и редиректить на логин.

Цель: Научиться централизованно обрабатывать сетевые запросы, не дублируя код в каждом компоненте.

3. Providers (Provide/Inject): Глобальный сервис уведомлений

Задача: Создать систему всплывающих уведомлений (Toasts). Используя provide в корневом компоненте App.vue, передать функцию showNotification(text, type) вниз по дереву. В любом глубоко вложенном компоненте использовать inject и вызывать эту функцию.

Цель: Понять, как передавать зависимости (провайдеры) на любую глубину без "Prop Drilling" (передачи пропсов через 10 уровней).

4. Providers (Plugins + Pinia): Глобальное состояние пользователя

Задача: Создать хранилище Pinia useUserStore. В нем хранить данные профиля и методы login() / logout(). Сделать так, чтобы при обновлении страницы данные подтягивались из localStorage. Использовать стор в навигационном хуке (из задачи 1).

Цель: Освоить современный подход к провайдингу глобального состояния.

5. Policies (Custom Directives): Скрытие элементов по правам

Задача: Создать кастомную директиву v-permission. Использование: <button v-permission="'delete-post'">Удалить</button>. Если в глобальном сторе (из задачи 4) у текущего юзера нет права delete-post, директива должна физически удалить этот элемент из DOM.

Цель: Реализовать "Политики" (права доступа) на фронтенде, чтобы не показывать пользователю кнопки, которые ему недоступны.

6. Cache (KeepAlive): Сохранение состояния формы

Задача: Есть компонент с большой формой (10 полей). Пользователь заполняет половину, переходит на другую вкладку, а затем возвращается. Использовать встроенный компонент <KeepAlive>, чтобы данные формы и позиция скролла не сбрасывались.

Цель: Понять, как Vue кеширует инстансы компонентов, чтобы не уничтожать их состояние при переключении роутов.

7. Cache (LocalStorage): Кеширование справочника стран

Задача: При загрузке компонента делать запрос к API за списком стран. Сохранять этот список в localStorage с временной меткой. При следующем открытии, если прошло меньше 24 часов — брать данные из localStorage (кеша), а не делать запрос к API.

Цель: Научиться реализовывать клиентское кеширование данных, чтобы экономить трафик и ускорять загрузку.

8. Sessions (State Management): Сессия в localStorage vs sessionStorage

Задача: При авторизации галочка "Запомнить меня" сохраняет JWT-токен в localStorage (сессия живет вечно), а без галочки — в sessionStorage (сессия живет до закрытия вкладки). При старте приложения проверять оба хранилища для восстановления сессии.

Цель: Понять разницу между постоянной и временной клиентской сессией.

9. Queues (Async operations): Последовательная загрузка файлов

Задача: Пользователь выбирает 3 файла для загрузки. Написать функцию, которая будет загружать их строго по очереди (используя async/await и цикл for...of). Каждый файл должен иметь свой прогресс-бар. Пока файл №1 не загрузится, файл №2 не должен начинать отправку.

Цель: Реализовать концепцию очереди на клиенте, чтобы не перегружать сервер параллельными запросами и не ловить ошибки таймаута.

10. Всё вместе: Дашборд аналитики

Задача: Собрать страницу, которая:

Защищена Route Guard'ом (Middleware);
Берет данные пользователя из Pinia (Provider);
Показывает кнопку "Экспорт в Excel" только директору (Policy);
Кеширует результаты тяжелого графика в computed свойстве (Cache);
При нажатии на кнопку показывает уведомление об успехе через инжект-сервис.
Цель: Объединить все архитектурные паттерны в одном комплексном интерфейсе.
